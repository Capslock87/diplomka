# Дипломный проект: Интернет-магазин одежды "LUMINA"

**Тема:** Основы проектирования интернет-магазинов одежды.

Этот проект представляет собой учебный макет frontend-части интернет-магазина одежды, разработанный с использованием чистого HTML5, CSS3 и Vanilla JavaScript без применения внешних библиотек и фреймворков.

## 📁 Структура проекта

Проект организован по классической структуре статического веб-сайта:

```
/
├── index.html        # Главная страница (Hero-баннер, популярные товары, преимущества)
├── catalog.html      # Каталог (вывод товаров, фильтрация по категориям, сортировка)
├── product.html      # Страница отдельного товара (описание, выбор размера, добавление в корзину)
├── cart.html         # Корзина (список товаров, изменение количества, удаление, общая сумма)
├── checkout.html     # Оформление заказа (форма контактов, адреса, имитация оплаты онлайн)
├── README.md         # Описание проекта
├── css/
│   └── style.css     # Основной файл стилей (CSS переменные, Flexbox/Grid, медиа-запросы)
└── js/
    ├── products.js   # "База данных" - массив с объектами товаров
    ├── main.js       # Общие утилиты (мобильное меню, всплывающие уведомления)
    ├── cart.js       # Ядро корзины (класс ShoppingCart, работа с localStorage)
    ├── catalog.js    # Логика рендеринга, фильтрации и сортировки товаров на странице каталога
    ├── product.js    # Логика динамического отображения информации о товаре по ID из URL
    ├── cart-page.js  # Логика управления UI корзины (плюс/минус количество, пересчет итогов)
    └── checkout.js   # Валидация формы заказа и имитация платежного шлюза
```

## 🛒 Принципы электронной коммерции

При разработке данного интерфейса учитывались современные паттерны e-commerce:

1.  **Пользовательский опыт (UX/UI):**
    *   **Минимализм:** Акцент сделан на контенте (фотографии товаров) благодаря чистым интерфейсам, обилию whitespace и нейтральной цветовой палитре.
    *   **Навигация:** Простое и понятное меню с индикаторами текущей страницы и постоянным доступом к корзине. Хлебные крошки (breadcrumbs) на странице товара.
    *   **Отзывчивость (Responsiveness):** Полная адаптация под мобильные устройства (flexbox, grid, медиа-запросы), мобильное "бургер"-меню.
    *   **Микроинтеракции:** Hover-эффекты на кнопках, карточках товаров, плавные анимации появления и добавления в корзину (всплывающие toast-уведомления).

2.  **Архитектура каталога:**
    *   Возможность выбрать категорию (фильтр) и отсортировать товары (по цене).
    *   Четкая карточка товара: визуальное представление (картинка), категория, название, цена, кнопка быстрого действия.

3.  **Customer Journey (Путь клиента):**
    *   Интуитивно понятный сценарий: Главная -> Каталог -> Товар -> Корзина -> Оформление -> Подтверждение.
    *   Empty-states: специальные экраны для пустой корзины, пустого поиска или несуществующего товара, предлагающие пути возврата в каталог.

## 📦 Реализация корзины

Корзина реализована на стороне клиента с использованием ООП и Browser Storage:

*   **Класс `ShoppingCart` (`cart.js`):** Инкапсулирует логику хранения массива объектов-товаров (с выбранным размером и количеством).
*   **Персистентность (`localStorage`):** При каждом изменении корзины данные сериализуются в JSON и сохраняются в `localStorage` браузера (`lumina_cart`). При перезагрузке страницы корзина восстанавливает свое состояние, что предотвращает потерю данных клиентом.
*   **Динамический бейджик:** Значок в хедере с общим количеством товаров обновляется мгновенно через вызовы методов класса Cart и генерацию пользовательских `CustomEvent`.
*   **Управление:** На странице корзины (`cart-page.js`) пользователи могут динамически изменять количество (кнопки `+`/`-` или прямой ввод), при этом цена товара и итоговая сумма пересчитываются моментально (DOM Manipulation).

## 🔒 Безопасность оплаты (на уровне фронтенда)

Так как проект является макетом, реальной обработки платежей (эквайринга) не происходит. Тем не менее, в файле `checkout.js` реализована базовая концепция "защиты от дурака" на фронтенде перед отправкой данных:

*   **Валидация формата:**
    *   *Имя*: Проверка на наличие только букв (исключаются цифры и спецсимволы в имени).
    *   *Email*: RegEx проверка базовой структуры `*@*.*`.
    *   *Телефон*: Очистка от масок и проверка минимальной длины номера (не менее 10 цифр).
*   **Имитация безопасного ввода данных карты:**
    *   *Номер карты*: Автоматическое форматирование (добавление пробела каждые 4 цифры) и ограничение длины (макс. 16 цифр/19 символов). Выполняется строгая проверка длины введенных цифр перед "отправкой".
    *   *Срок действия*: Форматирование `ММ/ГГ`. Защита от ввода несуществующих месяцев (>12), а также проверка, не истек ли срок действия карты (сравнение с текущим годом).
    *   *CVC/CVV-код*: Ограничено 3 цифрами. Поле типа `password`, чтобы код скрывался при вводе "за плечом" (shoulder surfing).
*   **Блокировка UI:** При успешной валидации и нажатии на "Подтвердить", кнопка блокируется стейтом `disabled`, и показывается индикатор "Обработка...", чтобы предотвратить двойное списание средств при многократном клике.
